# LogLens v0.1 research model card

## Intended use

Flag incident windows in application/system logs and rank the log lines that most likely explain
them, on a laptop CPU with no API calls. It is a *perception layer* for on-call engineers and AI SRE
agents: it does not generate explanations.

## Model

- Log-aware tokenizer: ordered regex masking (`<TS> <UUID> <IP>:<PORT> <PATH> <HEX> <BLK> <ID>
  <DURATION:bucket> <NUM> <VER> <LOC>`) + byte-level BPE (16k vocab), with `<LVL:x> <SVC:y>` prefix
  tokens.
- Line encoder: pre-LN transformer, 8 layers, d=512, 8 heads, FFN 2048, 128 max tokens, mean pool +
  linear -> 256-d line embedding; MLM pretrained on distinct masked lines.
- Window model: 4 layers, d=256, 4 heads, 256-line windows; inputs = line embedding + log-bucketed
  time gap + service + level embeddings; heads: anomaly (`[CLS]`), per-line suspicion, and masked
  template prediction (unsupervised scoring).
- Serving: ONNX Runtime (dynamic int8), template/embedding LRU cache.

## Training data

Loghub (BGL, HDFS_v1, OpenStack, Hadoop, Spark [6M-line cap], Zookeeper, Linux, Apache, HPC, SSH, Mac,
HealthApp, Proxifier, Android_v1) plus a simulated microservice fault lab. Thunderbird (first 6M
lines) is held out entirely as the *unseen* system. Loghub datasets are released for research use;
see https://github.com/logpai/loghub for the per-dataset terms before redistributing anything.
Splits are chronological (70/10/20; sessions assigned by first timestamp).

## Limitations

- Fault-lab incidents are **synthetic** (simulator, not real containers); root-cause numbers
  measure the model against the simulator's fault taxonomy, not real production incidents.
- Only the listed systems were tested; English-ish logs; logs with heavy non-English text
  (Android) tokenize poorly.
- Masking removes identifiers and numbers by design; incidents whose only signal is a specific
  numeric value can be missed.
- Test-time template leakage is high on several systems (see `docs/data_report.md`); in-distribution
  F1 on BGL/HDFS overstates generalisation, which is why the unseen-system transfer is reported.
- No frontier-LLM API baseline was run (no API key available in the build environment).

## Compute

One RTX 3050 6 GB laptop GPU for pretraining, fine-tuning and local LLM comparison; LogLens serving uses CPU.

## Follow-up validation

Six fault/recovery scenarios passed on a real Docker lab in Linux CI. This validates the lab,
not the synthetic model's published Recall@5. A separate Qwen2.5-1.5B single-call diagnosis pilot
identified 3/6 root-cause services with LogLens-selected lines versus 1/6 using raw prefixes.
The 36-case synthetic comparison was 31/36 versus 6/36. Both use a 1,500 text-token budget;
raw prefixes are truncated. These small controlled studies do not establish production accuracy.
